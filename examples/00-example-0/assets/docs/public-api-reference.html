The left-side catalog stays grouped and searchable; this page does the deeper explanation work.

How to use this page

Choose an API group from the catalog to jump here. Start with the guidance cards in each section, then use the inventory lists as a lookup table once you already know the right surface. Core Rendering Primitives

uistablecore

The base rendering surface for composing nodes, creating host elements, and turning component trees into HTML or live DOM output.

Use When

You need to build UI trees, render a root into the browser, or produce HTML on the server. This is the layer for composition and output, not for business workflow.

Avoid When

You are trying to solve caching, routing, validation, or cross-component data flow by hand inside render functions. Reach for fetch, router, forms, or state instead.

How It Works

CreateElement, Fragment, and Text define trees. Render and RenderInto mount them. RenderToString is the server-side path.

Recommended Pattern

Keep rendering pure. Compute values before the returned tree, then emit a stable node shape.

func App() ui.Node {
    headline := "Orders"
    return Div(
        H1(Text(headline)),
        P(Text("Review the current order queue.")),
    )
}

Avoid This Shape

Do not trigger imperative work during render.

func App() ui.Node {
    users, _ := http.Get("/api/users")
    _ = users
    return Div(Text("Loaded"))
}
Common Misuse

Calling network, storage, or long-running work directly during render. That creates unstable output and duplicate work across rerenders. Side effects belong in hooks or resource APIs.

HTML Element Constructors

htmlstablebeginner

Semantic HTML helpers for page structure, forms, links, media, and resource hints.

Use When

You want Go-authored UI to read like HTML, keep semantic structure obvious, and attach props and handlers through typed helpers.

Avoid When

You are trying to hide weak semantics behind generic containers. Prefer the element that matches intent instead of treating everything as a Div.

How To Think About It

The html package is the vocabulary layer. It does not replace state, routing, or forms; it gives those layers a semantic host tree.

Recommended Pattern

Use semantic wrappers first, then only fall back to Tag or CustomElement when there is no first-class helper.

Form(
    Label(For("email"), Text("Email")),
    Input(ID("email"), Type("email"), Placeholder("you@example.com")),
    Button(Type("submit"), Text("Save")),
)

Avoid This Shape

Do not flatten everything into anonymous containers.

Div(
    Div(Text("Email")),
    Div(Text("Save")),
)
Common Misuse

Stuffing framework behavior into Props.Raw first. Use typed props when they exist; reserve raw/property escape hatches for browser interop or unsupported attributes.

Hooks And Reactive Effects

uistablecore

Component-local state, memoization, effects, transitions, events, and task helpers.

Use When

You need component-local lifecycle, local state, derived view values, stable event handlers, or cancellable async work that belongs to one subtree.

Avoid When

You need app-wide state shared across unrelated branches, persisted cache, or route data. Local hooks are not a substitute for the state, fetch, or router packages.

How To Choose

UseState for local mutable view state, UseMemo for derived values, UseEffect for side effects, UseEvent for stable handlers, and UseTask/UseWorkerTask for explicit async units.

Recommended Pattern

query := ui.UseState("")
submit := ui.UseEvent(func() {
    logSearch(query.Get())
})

return Input(
    Value(query.Get()),
    OnInput(ui.UseEvent(func(e ui.InputEvent) {
        query.Set(e.GetValue())
    })),
)

Avoid This Shape

Do not mirror derivable state through effects.

count := ui.UseState(0)
  label := ui.UseState("0")

  ui.UseEffect(func() func() {
    label.Set(fmt.Sprintf("%d", count.Get()))
    return nil
  }, count.Get())
Common Misuse

Using UseEffect to mirror state into more state when the value could be computed directly. Prefer derivation over synchronization.

Composition, Context, And Boundaries

uistableintermediate

Context providers, lazy nodes, async boundaries, error boundaries, and reactive region isolation.

Use When

You need to isolate failures, delay expensive subtrees, share values down a tree without prop drilling, or scope reactive updates to smaller regions.

Avoid When

You are using context or lazy boundaries just to hide unclear component boundaries. These tools help good architecture; they do not rescue confused ownership.

How To Choose

CreateContext and UseContext for ambient values, ErrorBoundary for containment, AsyncBoundary/Lazy for delayed subtrees, and ReactiveRegion when update isolation is the real goal.

Recommended Pattern

ErrorBoundary(ErrorBoundaryProps{
    Fallback: Div(Text("Something failed.")),
    Child:    ui.Component(renderCheckoutPanel),
})

Avoid This Shape

Do not wrap the entire app with no recovery boundary plan.

ErrorBoundary(ErrorBoundaryProps{
    Child: ui.Component(renderWholeApp),
})
Common Misuse

Wrapping the whole app in boundaries without a recovery plan. Boundaries should align with user-visible recovery zones, not hide every error globally.

Accessibility, Focus, And Overlays

uistablecore

Focus control, announcements, composite navigation, overlays, portals, and stack coordination.

Use When

You are building overlays, menus, dialogs, composite widgets, or flows where keyboard and focus behavior is part of the feature, not a polish task.

Avoid When

You only need static semantics. Native labels, headings, buttons, and form controls should stay native before reaching for overlay and focus orchestration APIs.

How To Choose

UseFocusManager for explicit focus movement, UseFocusTrap and Overlay/AccessibleOverlay for layered UI, and UseAnnouncer when users need status changes spoken aloud.

Recommended Pattern

AccessibleOverlay(AccessibleOverlayProps{
    Open: true,
    Modal: true,
    Role: "dialog",
    InitialFocusSelector: "#confirm",
    OnDismiss: closeDialog,
})

Avoid This Shape

Do not open layered UI with no dismissal or focus policy.

Overlay(OverlayProps{
    Open: true,
    Child: Div(Text("Menu")),
})
Common Misuse

Using portals or overlays without focus return, escape handling, or outside-click policy. If the layer changes interaction model, it must also manage focus and dismissal.
